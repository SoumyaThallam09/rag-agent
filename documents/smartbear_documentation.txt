Squad to Zephyr Upgrade Guide
Squad to Zephyr Upgrade Guide
This guide helps teams upgrade from Zephyr Squad to Zephyr. It describes the upgrade paths, the migration process, and the key considerations to plan for. Zephyr offers improved performance, advanced automation, and a modern user experience.
Before you begin
Review the following availability limitations before you plan an upgrade:
Zephyr Squad to Zephyr Essential and Zephyr Squad to Zephyr upgrades are not currently supported on the Atlassian Forge platform.
Migration does not work on Zephyr Squad version 8.2.11 or later.
SmartBear is working to resolve both limitations. If either applies to you, contact SmartBear support to confirm your options before you begin.
Why Upgrade to Zephyr?
Zephyr offers the following:
A consistent, modern experience with AI-powered automation workflows.
A high-performance backend that supports AI-powered features and advanced automation needs.
Support for advanced compliance and automation requirements.
Migration Status
The Squad to Zephyr migration is currently in beta. Because the tool is still in beta, the migration might not be seamless. You might encounter issues during the process, need to repeat steps, or find that some data needs to be reviewed before it is correct. Plan your upgrade with this in mind, and allow time to validate the results before you rely on the migrated data.
Assessment Phase
If you are a new customer planning an upgrade, you go through an assessment phase before your production migration. The assessment confirms that your data can migrate successfully and helps set realistic dates for the production migration.
During the assessment phase, the SmartBear team does the following:
Evaluates your migration eligibility to confirm that your Zephyr Squad configuration and version can migrate.
Performs a test migration of your data.
Review the test migration results with you to identify any issues.
Plan your production migration dates based on the outcome of the test migration.
This assessment and planning process remains in place until the migration tool reaches general availability (GA).

Zephyr

A
dedicated migration UI

Project-level migration
Progress tracking and retry options

The ability to migrate individual spaces
Migration runs space by space, so you can validate each space individually.
App Availability During Migration
Zephyr remains usable during the data migration. The app is not blocked by default, so you can continue creating or modifying data.
Note
Re-running the migration overwrites previously migrated data, and any existing data in Zephyr is also overwritten. Merging and delta migrations are not supported. If you add or update data in Zephyr Squad after a migration and want those changes to appear in Zephyr, you must re-run the migration.
To prevent data inconsistencies, the migration user interface lets you block Zephyr Squad during migration. Blocking is optional, but SmartBear recommends it to protect data integrity.
Environment Options
Production Migration.
Fully supported. Zephyr Squad is usable during migration.
Sandbox Migration.
Possible, but requires manual setup. Squad data cannot be copied directly from production. Use
CSV export/import
for test cases and test steps.
Note
The CSV export/import feature supports only importing test cases and test steps. It does not support importing test cycles or test executions.

Upgrade to

The discount is in the form of a promo code that you can use to apply to the new Zephyr subscription. You can let the Zephyr Squad license expire.
During the upgrade/UAT phase, we can arrange for dual licensing upon request. We provide a limited free license if you have a paid or commercial license in place. If you have any questions about licenses, feel free to email
[email protected]

Test cycle folder structure
In Squad, a test cycle is created under a fix version. Fix versions can be in released or in unreleased state and the tree structure to organize test cycles are grouped by it. By default, a fix version named Unscheduled and a test cycle named Ad-hoc for each fix versions is present. Test cycles can have one more level called Test folder under it.
In
Zephyr
/ Zephyr Essential, the folder hierarchy is created first and for each folder test cycles can be created. Folder structure are present for n-levels and fix versions are present as a field for the test cycle.
For migrating data from Squad to
Zephyr
/ Zephyr Essential, the test cycle and folder hierarcy under the fix versions is migrated as the folder structure in
Zephyr
/ Zephyr Essential. The executions present for each of these cycles and folders is added by creating a test cycle each under the respective folder node. The test cycle is given a name with the folder name prefix for example, login-cycle. The fix version for these test cycles is added as the fix version field value for the test cycle.
Ad hoc test cycles executions is migrated to folder named Ad hoc and by creating multiple test cycles with each fix versions added to it.

Test case change history
To migrate Squad test case history to
Zephyr
/ Zephyr Essential we need to combine data from the Jira issue history and the “Test Details History” tab.
From the “Test Details History” tab we need to get data about changes made to Squad test steps.
From the Jira issue history, we need to get all the data available there.
After getting the data from both Squad histories we need to sort it based on the time that the change was made. (sort by date and time to get the right order.)
After sorting the data we import it to
Zephyr
/ Zephyr Essential as a separate change event to the test case.
